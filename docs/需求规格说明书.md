# 需求规格说明书

## 1. 项目目标

提供一套界面成熟、权限边界清晰、可直接扩展业务模块的后台管理系统模板。模板不绑定具体行业，
新项目可以在用户、角色、菜单和统一接口规范之上继续开发。

## 2. 用户角色

| 角色 | 说明 | 默认权限 |
|---|---|---|
| 超级管理员 | 系统所有者 | 用户、角色、菜单及授权管理 |
| 系统管理员 | 日常运营人员 | 工作台、个人中心、用户管理 |

## 3. 功能需求

### 3.1 认证与会话

- 用户名、密码登录。
- 密码使用 BCrypt 哈希存储。
- 登录成功签发访问令牌和刷新令牌。
- 访问受保护接口时校验 Bearer Token。
- 停用账号不能登录。

### 3.2 个人中心

- 登录用户可查看自己的账号、姓名、昵称、联系方式、头像、简介、角色和注册时间。
- 登录用户可维护自己的姓名、昵称、性别、邮箱、手机和个人简介，不在个人中心采集联系地址。
- 登录用户可点击个人中心左侧资料卡头像修改自己的头像；右侧基本设置不重复提供头像字段。头像仅支持 JPG、PNG、WebP，单个文件不超过 2MB。
- 用户名、角色和注册时间在个人中心只读。
- 修改密码必须校验当前密码，新密码需二次确认并采用 BCrypt 哈希存储。
- 密码修改成功后退出当前会话并重新登录。

### 3.3 用户管理

- 按用户名、手机号、邮箱、性别、状态分页查询。
- 新增用户时设置初始密码和至少一个角色。
- 编辑基本信息、状态、角色，可选择重置密码。
- 注销用户使用逻辑删除；内置超级管理员不可注销。

### 3.4 角色管理

- 分页查询、新增、编辑、删除角色。
- 角色编码全局唯一。
- 为角色分配菜单和按钮权限。
- 内置超级管理员角色不能删除或变更编码。
- 仍被用户使用的角色不能删除。

### 3.5 菜单管理

- 查询菜单/按钮树。
- 新增、编辑、删除菜单节点和按钮权限。
- 菜单支持路由、组件、图标、排序、缓存、隐藏、徽章等前端属性。
- 有子节点的菜单不能直接删除。

### 3.6 公告管理

- 超级管理员和系统管理员可分页查询、新增、编辑和删除公告。
- 公告支持系统公告、活动公告、提醒通知三种类型。
- 公告支持草稿、已发布两种状态；从草稿切换为已发布时记录发布人和发布时间。
- 公告支持置顶，列表按置顶、发布时间和创建时间倒序排列。
- 可按标题、公告类型和发布状态筛选。
- 删除公告使用逻辑删除，已删除数据不再出现在管理列表中。

### 3.7 日志管理

- 系统自动记录后台新增、编辑、发布、删除、上传和消息发送等写操作。
- 登录成功、用户名或密码错误、登录参数异常均写入同一张日志表，并标记为登录日志。
- 日志包含日志类型、账号、HTTP 方法、接口路径、查询参数、执行结果、状态码、IP、浏览器标识和耗时。
- 日志不得保存密码、Token、上传文件内容或请求正文，避免二次泄露敏感信息。
- 仅超级管理员可以分页查询、删除单条日志和清空日志。
- 页面提供“系统日志”和“登录日志”两个横向切换入口，一次只展示当前选择的日志类型。
- 系统日志可按账号、接口路径、HTTP 方法和执行结果筛选；登录日志可按账号和登录结果筛选。

### 3.8 文件管理

- 超级管理员和系统管理员可上传、查询、下载和删除文件。
- 上传文件默认不超过 20MB，只允许图片、PDF、纯文本、CSV、Markdown、Office 文档和 ZIP 压缩包。
- 服务端使用随机存储名，原始文件名只作为展示和下载名称，禁止客户端控制保存路径。
- 文件保存路径必须限制在专用存储目录内，下载和删除时校验规范化路径，防止路径穿越。
- 数据库保存原始名称、存储名称、内容类型、大小、上传人和上传时间；删除时同步移除物理文件并逻辑删除元数据。

### 3.9 消息通知

- 超级管理员和系统管理员可以向全部启用用户或指定用户发送消息。
- 消息支持系统消息、提醒消息、任务消息三种类型。
- 登录用户可查看自己的消息收件箱，按标题、类型和已读状态筛选。
- 登录用户可将单条消息设为已读，也可一键全部已读。
- 顶部通知入口展示最近消息和未读状态，可跳转到消息中心。
- 消息接收关系必须按当前用户校验，用户不能读取或修改其他用户的消息状态。

## 4. 非功能需求

- 后端使用 Java 17，接口采用 RESTful 风格。
- 接口统一返回 `{ code, msg, data }`。
- 所有输入在后端校验，权限必须在后端校验。
- 敏感配置只从环境变量获取。
- 前端 TypeScript 严格类型检查通过，后端必须完成测试和打包。

## 5. 本期不包含

- 图形验证码、短信、邮件、OAuth 等第三方登录。
- 租户、组织机构、数据字典、审计日志等行业扩展模块。
- 对象存储；当前头像和文件均使用本地持久化目录。
- 生产环境监控、限流、令牌黑名单和密钥轮换平台。

这些内容属于后续扩展，不应被视为当前已实现功能。

## 6. 验收标准

1. 前端 `pnpm lint` 和 `pnpm build` 成功。
2. 后端 `mvn clean test package` 成功。
3. MySQL 迁移成功后，两个初始账号可以登录。
4. 超级管理员可完成用户、角色、授权和菜单 CRUD。
5. 系统管理员不能访问角色、菜单管理接口。
6. 异常参数、未登录、无权限分别返回清晰的 400、401、403 语义；失败响应携带错误编号、稳定错误码、错误类型和请求路径，前端提示错误编号，服务端可据此检索完整日志。
7. 登录用户可加载并修改自己的资料；错误当前密码必须被拒绝且不得改变原密码。
8. 两个内置管理员角色可完成公告查询、新增、编辑、发布、取消发布和删除；未授权账号返回 403。
9. 写操作与登录成功/失败自动产生不含请求正文的日志，日志管理接口仅超级管理员可访问。
10. 管理员可完成允许类型文件的上传、下载和删除，路径穿越和超限文件必须被拒绝。
11. 管理员可发送消息，接收人可查看未读数量并完成单条或全部已读，跨用户访问必须被拒绝。

## 1.1.0 安全与正确性验收补充

- 停用、改密、用户管理更新后旧访问和刷新令牌失效；退出仅撤销当前会话；用户名重新分配不能使旧令牌绑定到其他用户。
- 普通管理员只能管理权限范围内的账号和角色；自定义业务角色可按模块授权使用功能，授权管理功能仍由超级管理员负责。
- 取消按钮权限后直接调用后端同样拒绝；发布公告不能借用新增或编辑接口绕过发布权限。
- 用户编辑不强制改密码；字段清空必须落库；逻辑删除名称冲突返回可理解的提示。
- 文件回滚保留旧头像并清理新文件；日志清空动作本身需要留下后续审计记录。
