# 接口设计文档

## 1. 通用约定

- 基础地址：`http://localhost:8080`
- 内容类型：`application/json`
- 认证头：`Authorization: Bearer <accessToken>`
- 统一响应：

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {}
}
```

失败响应保持 `code`、`msg`、`data` 兼容，并增加 `error` 追踪信息：

```json
{
  "code": 404,
  "msg": "用户不存在",
  "data": null,
  "error": {
    "errorId": "ERR-1A2B3C4D5E6F",
    "errorCode": "RESOURCE_NOT_FOUND",
    "errorType": "RESOURCE",
    "method": "DELETE",
    "path": "/api/user/999",
    "timestamp": "2026-08-11 14:45:00"
  }
}
```

`errorId` 用于在服务端日志中检索同一次异常。响应不返回异常类名、堆栈、数据库语句、文件绝对路径、
请求正文、密码或令牌。

| errorCode | errorType | code | 说明 |
|---|---|---:|---|
| `REQUEST_VALIDATION` | `VALIDATION` | 400 | 参数校验、类型转换或 JSON 格式错误 |
| `FILE_UPLOAD_ERROR` | `VALIDATION` | 400 | 上传大小或上传请求不符合要求 |
| `AUTHENTICATION_REQUIRED` | `AUTHENTICATION` | 401 | 未登录、Token 或刷新令牌失效 |
| `ACCESS_DENIED` | `AUTHORIZATION` | 403 | 角色或方法权限不足 |
| `RESOURCE_NOT_FOUND` | `RESOURCE` | 404 | 业务记录或静态资源不存在 |
| `METHOD_NOT_ALLOWED` | `VALIDATION` | 405 | 请求方法不支持 |
| `BUSINESS_ERROR` | `BUSINESS` | 400 | 业务规则不满足 |
| `FILE_STORAGE_ERROR` | `SYSTEM` | 500 | 文件保存、读取或删除失败 |
| `DATA_ACCESS_ERROR` | `SYSTEM` | 500 | 数据库访问失败 |
| `SYSTEM_ERROR` | `SYSTEM` | 500 | 未知系统异常 |

## 2. 认证接口

| 方法 | 路径 | 认证 | 说明 |
|---|---|---|---|
| POST | `/api/auth/login` | 否 | 登录 |
| POST | `/api/auth/refresh` | 否 | 使用刷新令牌换取新令牌 |
| GET | `/api/user/info` | 是 | 当前用户信息、角色和按钮权限 |

登录请求：

```json
{
  "userName": "admin",
  "password": "Admin@123"
}
```

## 3. 个人中心接口

个人中心写接口均作用于当前 Bearer Token 对应的登录用户，不接收用户 ID，普通登录用户也可以访问。
头像读取地址为公开只读资源，文件名由服务端随机生成。

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | `/api/profile` | 登录用户 | 查询当前用户资料和角色 |
| PUT | `/api/profile` | 登录用户 | 修改当前用户基本资料 |
| POST | `/api/profile/avatar` | 登录用户 | 上传并立即更新当前用户头像 |
| GET | `/api/profile/avatar/{fileName}` | 公开只读 | 读取服务端保存的头像 |
| PUT | `/api/profile/password` | 登录用户 | 校验当前密码后修改密码 |

修改资料请求：

```json
{
  "realName": "张三",
  "nickname": "管理员",
  "gender": 1,
  "phone": "13800000000",
  "email": "admin@example.com",
  "bio": "负责系统日常维护"
}
```

用户名、角色和注册时间为只读信息。个人资料接口不接收头像地址和联系地址。

头像上传使用 `multipart/form-data`，字段名为 `file`。仅支持 JPG、PNG、WebP，最大 2MB；后端同时校验
MIME、扩展名和文件头。上传成功返回更新后的完整个人资料，头像地址形如
`/api/profile/avatar/{随机文件名}`。

修改密码请求：

```json
{
  "currentPassword": "当前密码",
  "newPassword": "NewPassword123",
  "confirmPassword": "NewPassword123"
}
```

新密码长度为 8 到 64 个字符，必须同时包含字母和数字。修改成功后前端清理当前会话并要求重新登录。

## 7. 公告管理接口

公告管理接口统一要求 `R_SUPER` 或 `R_ADMIN` 角色。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/announcement/list` | 分页查询公告，可按标题、类型、状态筛选 |
| POST | `/api/announcement` | 新增公告 |
| PUT | `/api/announcement/{id}` | 编辑公告 |
| PUT | `/api/announcement/{id}/status` | 发布或取消发布公告 |
| DELETE | `/api/announcement/{id}` | 逻辑删除公告 |

公告保存请求：

```json
{
  "title": "系统维护通知",
  "content": "系统将于本周六进行例行维护。",
  "type": "SYSTEM",
  "status": "PUBLISHED",
  "top": true
}
```

状态变更请求：

```json
{
  "status": "DRAFT"
}
```

当状态首次变为或再次切换为 `PUBLISHED` 时，后端使用当前认证账号写入发布人和发布时间；切换为
`DRAFT` 时清空发布信息。

## 8. 日志管理接口

日志管理接口仅允许 `R_SUPER`。操作日志和登录日志写入同一张表，通过 `logType` 区分。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/log/list` | 按类型、账号、路径、方法、结果分页查询 |
| DELETE | `/api/log/{id}` | 删除单条日志 |
| DELETE | `/api/log/clear` | 清空全部操作与登录日志 |

`logType` 可选值为 `OPERATION`、`LOGIN`。登录日志记录登录成功与失败，账号来自登录请求中的 `userName`；
日志仅记录接口元信息，不返回或保存请求正文、密码或令牌。

## 9. 文件管理接口

文件接口要求 `R_SUPER` 或 `R_ADMIN`。

| 方法 | 路径 | 内容类型 | 说明 |
|---|---|---|---|
| GET | `/api/file/list` | - | 按文件名和内容类型分页查询 |
| POST | `/api/file` | `multipart/form-data` | 上传单个文件，字段名 `file` |
| GET | `/api/file/{id}/download` | - | 下载文件流 |
| DELETE | `/api/file/{id}` | - | 删除物理文件并逻辑删除元数据 |

默认最大文件大小为 20MB。下载接口直接返回二进制流和 `Content-Disposition`，不使用统一 JSON 包装。

## 10. 消息通知接口

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | `/api/message/list` | 登录用户 | 查询当前用户收件箱 |
| GET | `/api/message/unread-count` | 登录用户 | 查询当前用户未读数量 |
| PUT | `/api/message/{receiverId}/read` | 登录用户 | 将属于当前用户的消息设为已读 |

## 1.1.0 权限与会话变更

响应仍保持 `{ code, msg, data }`。新增 `POST /api/auth/logout`，携带当前访问令牌，撤销当前设备会话，其他设备不受影响。

登录、刷新响应字段保持 `token` 与 `refreshToken`。刷新令牌单次使用，客户端必须原子替换两个令牌；同一页面的并发 401 合并一次刷新。会话绝对期限由首次登录时的 `JWT_REFRESH_DAYS` 决定，刷新不会延长数据库中的截止时间。升级前令牌不接受，需重新登录。

业务权限由已授权且启用的菜单树计算，命名方式为 `路由名:动作`，保留旧菜单中的 `add` 等按钮值供前端使用。父级未授权、停用或出现层级循环时不赋予子级权限。

| 模块 | 读权限 | 写权限 |
|---|---|---|
| 用户 | User:read | User:add / User:edit / User:delete |
| 公告 | Announcement:read | Announcement:add / Announcement:edit / Announcement:publish / Announcement:delete |
| 文件 | FileManage:read | FileManage:upload / FileManage:download / FileManage:delete |
| 消息 | 个人收件箱与已读操作按当前用户隔离 | MessageCenter:send |

`R_SUPER` 拥有管理权限。角色、菜单和日志管理接口仍仅向超级管理员开放，不随业务菜单授权开放授权管理能力。非超级管理员不得操作超级管理员账号或分配超出自身有效权限的角色。公告新增即发布、修改已发布内容，也要求发布权限。

用户编辑允许省略密码或提交空字符串；非空密码仍要求8至64个字符。用户管理更新会撤销该账号旧令牌；个人中心修改一般资料不撤销会话，修改密码会撤销。

新增 `GET /api/message/receivers?keyword=`，需要 `MessageCenter:send` 或超级管理员权限，只返回最多100个启用账号的 `id/userName/nickName`。消息发送页面使用该接口，不需要用户管理权限。

## 1.1.1 接口变更

- `POST /api/auth/login`：同一账号在同一来源地址 15 分钟内失败 5 次后，返回 `code=429`、`errorCode=TOO_MANY_LOGIN_ATTEMPTS`，锁定期内不再校验密码。限流状态保存在进程内存，多实例部署需改用共享存储。
- `GET /api/v3/system/menus`：超级管理员返回全部启用菜单，不再受 `sys_role_menu` 影响。
- `PUT /api/role/{id}/menus`：对 `R_SUPER` 返回业务错误。
- `POST/PUT /api/menu`：按钮必须挂在菜单节点下，同一菜单下 `permission` 不能重复；`routeName`、`permission` 仅允许字母开头的字母、数字、下划线和短横线；`externalLink` 仅允许 http/https；已有菜单的 `routeName` 不能修改。空字符串按 NULL 处理。
- `POST/PUT /api/user`：请求中的 `avatar` 字段保留兼容但不再写入；密码须为 8～64 位且同时含字母和数字；不能停用当前登录账号；只有账号、状态、密码或角色变化才撤销该用户会话。
- `POST /api/message`：`receiverIds` 最多 500 个。
- 缺少 multipart 文件、请求体类型不支持等返回 HTTP 400 和 `REQUEST_VALIDATION`。
