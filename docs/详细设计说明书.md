# 详细设计说明书

## 1. 登录流程

1. 前端提交用户名和密码到 `POST /api/auth/login`。
2. Spring Security 调用 `CustomUserDetailsService` 查询用户、角色和按钮权限。
3. BCrypt 校验密码，停用账号拒绝认证。
4. `JwtTokenProvider` 签发访问令牌和刷新令牌。
5. 前端持久化令牌，后续请求统一追加 Bearer Token。
6. 路由初始化时请求当前用户和动态菜单，注册可访问页面。

## 2. 个人中心

- `ProfileController` 只接受当前登录用户请求，不暴露可指定其他用户 ID 的入口。
- `ProfileService` 根据 Spring Security 认证上下文读取用户，返回资料、角色和注册时间。
- 保存资料时执行后端 Bean Validation，账号、角色、注册时间、头像和地址不允许通过资料 JSON 修改。
- `AvatarStorageService` 负责头像格式、扩展名、文件头和 2MB 大小校验，并使用 UUID 文件名保存到独立目录。
- 头像上传成功后立即更新当前用户；数据库更新失败时删除新文件，更新成功后清理旧的本地头像。
- 前端将头像上传触发器放在左侧个人资料卡头像上，悬停、键盘聚焦和上传中均展示明确状态；右侧基本设置只维护文字资料。
- 头像读取仅接受系统生成的文件名，访问路径经过规范化和根目录边界校验。
- 修改密码时依次校验当前密码、两次新密码一致、新旧密码不同，再生成新的 BCrypt 哈希。
- 前端保存基本资料后合并更新用户状态；密码修改成功后清理令牌并跳转登录页，避免旧会话继续使用。
- 个人中心路由由数据库动态下发并设置为隐藏，不占用侧边栏位置，可从头像菜单进入。

## 3. 用户保存

- 新增：校验用户名唯一、角色有效、初始密码不少于8个字符；一个事务内写入用户与用户角色。
- 编辑：保留原密码；只有提交非空密码时才重置 BCrypt 哈希。
- 注销：删除用户角色关系并逻辑删除用户；禁止操作内置管理员 ID 1。

## 4. 角色授权

- 前端权限树使用菜单数据库 ID 作为节点键。
- 保存时合并全选节点与半选父节点，避免只保存叶子后丢失目录。
- 后端先校验角色和全部菜单 ID，再在一个事务内替换角色菜单关系。

## 5. 菜单树转换

- 数据库使用 `parent_id` 存储树关系。
- `MENU` 转为 Vue Router 路由节点。
- `BUTTON` 不作为路由子节点，而是聚合到父菜单的 `meta.authList`。
- 当前用户菜单只查询已启用且已授权节点；菜单管理树可查看停用节点。

## 6. 公告管理

- `SysAnnouncement` 使用 MyBatis-Plus 逻辑删除，查询默认排除已删除记录。
- 分页查询将请求大小限制为 1 到 100，标题采用模糊查询，类型和状态采用精确查询。
- 保存前统一校验公告类型和状态枚举；标题长度不超过 150 个字符，正文长度不超过 10000 个字符。
- 新增或编辑为已发布状态时，使用当前认证用户名写入发布人和发布时间；改回草稿时清空发布信息。
- 列表按 `is_top`、`published_at`、`created_at` 倒序排列，置顶公告优先。
- Controller 通过 `R_SUPER`、`R_ADMIN` 方法权限保护，前端按钮权限只负责交互可见性，不作为安全边界。

## 7. 日志管理

- `OperationLogInterceptor` 拦截 `/api/**` 下的写请求并排除日志管理自身接口，同时单独识别 `POST /api/auth/login`。
- 拦截器只读取请求方法、URI、查询参数、认证用户、IP、User-Agent、响应状态和耗时，不读取请求体。
- 登录接口在调用认证服务前仅通过请求属性传递 `userName`；登录失败时不依赖认证主体，因此错误账号同样可以记录。
- 登录成功、业务失败和参数校验失败分别记录成功或失败结果；缺少有效账号字段的异常请求显示为“未知账号”。
- `log_type` 使用 `OPERATION`、`LOGIN` 区分两类记录，两类日志在同一列表查询、删除和清空。
- 前端不提供日志类型下拉框，使用“系统日志”和“登录日志”两个横向入口切换；页面一次只挂载当前日志内容，两类日志分别保留筛选、刷新和分页状态。
- 全局异常处理器通过请求属性标记业务失败，使 HTTP 200 包装的业务错误也能记录为失败。
- 日志写入异常只记录服务端警告，不影响原业务响应。

## 8. 文件管理

- 上传前同时校验文件非空、大小和内容类型；物理文件名由 UUID 与安全扩展名组成。
- 存储根目录来自 `FILE_STORAGE_ROOT`，默认使用后端工作目录下的 `data/files`。
- 保存、下载、删除前对规范化绝对路径执行 `startsWith(storageRoot)` 校验。
- 上传采用先写物理文件再写数据库；数据库失败时删除已写文件。删除采用事务内逻辑删除元数据并删除物理文件。
- 下载使用 Spring `Resource` 返回文件流，文件名通过 UTF-8 `Content-Disposition` 编码。

## 9. 消息通知

- 消息正文和接收状态分离，群发只保存一份正文并为每个启用用户创建接收记录。
- 指定接收人时校验用户存在、启用且未逻辑删除；接收人 ID 去重。
- 收件箱查询始终追加当前认证用户 ID，客户端不能通过参数指定其他接收人。
- 单条已读先校验接收记录归属，再写入 `read_at`；全部已读只更新当前用户未读记录。
- 顶部通知面板复用收件箱接口，打开时刷新最近消息，未读数量变化同步到顶部红点。

## 10. 异常处理

- `ApplicationException` 是应用异常基类，`BusinessException` 表示可预期业务失败，`SystemException` 表示文件、基础设施等需要记录堆栈的系统故障。
- `ErrorCode` 统一维护 HTTP/业务状态、稳定错误码、错误类型和默认安全文案；参数校验、认证、授权、业务、资源和系统错误分别归类。
- 每次失败由 `ErrorDetail` 生成 `ERR-` 开头的唯一错误编号，并记录错误码、请求方法、请求路径和发生时间。
- `GlobalExceptionHandler` 对业务错误记录结构化警告，对文件、数据库和未知系统异常记录带错误编号的完整堆栈。
- Spring Security 的未认证和权限拒绝处理器使用同一错误响应格式，因此 401、403 同样可以通过错误编号检索。
- 前端 `HttpError` 保存后端错误详情，消息提示展示错误编号，控制台日志保留错误码、分类、请求路径和服务端时间。
- 客户端不接收异常堆栈、数据库语句、文件绝对路径或请求敏感内容；运维人员使用错误编号在服务端日志中定位内部原因。

| 场景 | code | errorCode | 处理方式 |
|---|---:|---|---|
| 参数校验失败 | 400 | `REQUEST_VALIDATION` | 返回第一个可读字段错误和追踪信息 |
| 业务规则不满足 | 400 | `BUSINESS_ERROR` | 抛出 `BusinessException`，记录结构化警告 |
| Token 缺失/失效 | 401 | `AUTHENTICATION_REQUIRED` | 认证入口返回统一错误响应 |
| 角色权限不足 | 403 | `ACCESS_DENIED` | 权限处理器返回统一错误响应 |
| 资源不存在 | 404 | `RESOURCE_NOT_FOUND` | 区分业务记录和其他业务规则错误 |
| 文件存储失败 | 500 | `FILE_STORAGE_ERROR` | 返回安全文案，服务端记录原始异常堆栈 |
| 数据库访问失败 | 500 | `DATA_ACCESS_ERROR` | 返回安全文案，服务端记录原始异常堆栈 |
| 未知异常 | 500 | `SYSTEM_ERROR` | 返回安全文案，服务端记录原始异常堆栈 |

## 11. 扩展业务模块步骤

1. 新增数据库迁移。
2. 新增 Entity、Mapper、DTO/VO、`XxxService` 接口、`XxxServiceImpl` 业务实现和 Controller。
3. 在菜单管理中配置对应组件路径和按钮权限。
4. 在 `frontend/src/api/` 增加接口封装。
5. 新增页面、类型和测试。
6. 更新接口、数据库、测试和更新日志文档。
