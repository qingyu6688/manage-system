# 部署说明

## 1. 后端打包

在 `F:\桌面\manage-system\backend` 执行：

```powershell
mvn clean test package
```

产物：`target/manage-system-backend-1.0.0.jar`。

生产环境启动前设置：`DB_HOST`、`DB_PORT`、`DB_USER`、`DB_PASSWORD`、`DB_NAME`、
`JWT_SECRET`、`FILE_STORAGE_ROOT`、`AVATAR_STORAGE_ROOT`。禁止把真实值写入仓库。
两个存储目录应使用独立持久化路径，并授予后端进程读写权限。

```powershell
java -jar target/manage-system-backend-1.0.0.jar
```

## 2. 前端构建

在 `F:\桌面\manage-system\frontend` 执行：

```powershell
pnpm install --frozen-lockfile
pnpm build
```

将 `dist/` 部署到 Nginx 静态目录。

## 3. Nginx 示例

```nginx
server {
    listen 80;
    server_name example.com;
    client_max_body_size 21m;

    root /var/www/manage-system;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }

    location /api/ {
        proxy_pass http://127.0.0.1:8080/api/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

## 4. 上线检查

- 数据库备份完成，Flyway 迁移版本已核对。
- JWT 密钥长度不少于32字节，且与开发环境不同。
- MySQL 不对公网开放，数据库账号采用最小权限。
- HTTPS 已启用，生产环境不输出调试日志和异常堆栈。
- 初始密码已修改，演示账号按业务需要删除或停用。
- 前端静态资源和后端日志路径具备正确权限。
- 文件和头像存储目录已持久化，已纳入备份，并验证后端进程只能访问指定目录。

## 5. 回滚

- 应用回滚：保留上一版本 Jar 和前端静态目录，切换软链接后重启服务。
- 数据库回滚：Flyway 迁移默认只向前。涉及破坏性结构变更时，发布前准备独立回滚 SQL 和备份。
- 文件回滚：应用回滚不会自动恢复已删除文件，发布前应同时备份数据库、`FILE_STORAGE_ROOT` 和 `AVATAR_STORAGE_ROOT`，并保持同一时间点。
- 不直接修改已经执行的 Flyway 迁移文件。

## 1.1.0 升级步骤与恢复边界

1. 备份业务数据库以及实际 `FILE_STORAGE_ROOT`、`AVATAR_STORAGE_ROOT` 目录，记录当前 JAR 和静态资源版本。
2. 在测试环境验证 V1～V7；升级现有库时应只新增执行 V7，不能修改旧迁移历史。
3. 停止旧后端后部署 `manage-system-backend-1.1.0.jar`，提供稳定的 `JWT_SECRET` 和数据库环境变量，确认 Flyway V7 成功。
4. 部署同版本前端，检查登录、刷新、退出、角色权限与文件目录权限。所有用户需要重新登录。
5. 失败时保留数据库新增结构并按备份恢复方案处理，不直接删除会话表、版本列或迁移历史。不要将有权限缺陷的旧版本作为长期恢复目标。

默认关闭 SQL 标准输出。审计 IP 默认记录直连地址；反向代理场景应在可信代理配置中设置来源解析，不能直接信任客户端 X-Forwarded-For。

文件物理清理在数据库提交后执行，失败记录 `FILE_CLEANUP_FAILED` 或头像清理警告，需按日志中的存储文件名核对数据库引用后重试；本版未引入持久化后台清理队列。进程崩溃可能留下孤立文件，应定期对账。文件内容检查不替代杀毒系统。

后台数据库、文件目录和8080端口不应直接开放到公网；前端通过同源反向代理访问API。

## 1.1.1 升级步骤

1. 备份数据库后部署 `manage-system-backend-1.1.1.jar`，确认 Flyway V8 执行成功（只清理菜单表空串）。
2. 部署同版本前端。前端版本号变化会触发一次本地缓存清理和重新登录。
3. 登录失败限流按来源地址计数。若经 Nginx 反向代理且未配置可信代理解析，所有请求的来源地址相同，限流实际只按账号生效。
4. 若之前手动执行过迁移脚本建表、库中没有 `flyway_schema_history`，新版本会拒绝启动；应改为空库由 Flyway 初始化后再迁移数据。
