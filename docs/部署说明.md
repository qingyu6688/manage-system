# 部署说明

## 1. 后端打包

在 `F:\桌面\manage-system\backend` 执行：

```powershell
mvn clean test package
```

产物：`target/manage-system-backend-1.0.0.jar`。

生产环境启动前设置：`DB_HOST`、`DB_PORT`、`DB_USER`、`DB_PASSWORD`、`DB_NAME`、
`JWT_SECRET`、`FILE_STORAGE_ROOT`、`AVATAR_STORAGE_ROOT`。禁止把真实值写入仓库。
两个存储目录应使用独立持久化路径，并授予后端进程读写权限。

```powershell
java -jar target/manage-system-backend-1.0.0.jar
```

## 2. 前端构建

在 `F:\桌面\manage-system\frontend` 执行：

```powershell
pnpm install --frozen-lockfile
pnpm build
```

将 `dist/` 部署到 Nginx 静态目录。

## 3. Nginx 示例

```nginx
server {
    listen 80;
    server_name example.com;
    client_max_body_size 21m;

    root /var/www/manage-system;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }

    location /api/ {
        proxy_pass http://127.0.0.1:8080/api/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

## 4. 上线检查

- 数据库备份完成，Flyway 迁移版本已核对。
- JWT 密钥长度不少于32字节，且与开发环境不同。
- MySQL 不对公网开放，数据库账号采用最小权限。
- HTTPS 已启用，生产环境不输出调试日志和异常堆栈。
- 初始密码已修改，演示账号按业务需要删除或停用。
- 前端静态资源和后端日志路径具备正确权限。
- 文件和头像存储目录已持久化，已纳入备份，并验证后端进程只能访问指定目录。

## 5. 回滚

- 应用回滚：保留上一版本 Jar 和前端静态目录，切换软链接后重启服务。
- 数据库回滚：Flyway 迁移默认只向前。涉及破坏性结构变更时，发布前准备独立回滚 SQL 和备份。
- 文件回滚：应用回滚不会自动恢复已删除文件，发布前应同时备份数据库、`FILE_STORAGE_ROOT` 和 `AVATAR_STORAGE_ROOT`，并保持同一时间点。
- 不直接修改已经执行的 Flyway 迁移文件。
