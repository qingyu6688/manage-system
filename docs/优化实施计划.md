# 优化实施计划

日期：2026-09-13。目标版本：1.1.0。维护备注：maorongkang@gmail.com。

## 计划一：权限与会话安全

- 范围：限制用户管理的目标账号与可分配角色；业务接口按模块权限校验；角色、菜单及日志管理仍由超级管理员掌握。
- 会话设计：JWT 绑定不可变用户 ID 和账号会话版本；数据库保存会话及刷新令牌摘要；刷新通过条件更新实现单次使用；退出撤销当前会话；停用、改名、改密和角色调整使旧令牌失效。
- 前端：401 时合并并发刷新，刷新失败再退出；主动退出调用后端撤销接口。
- 数据库：新增 V7 迁移，保留 V1～V6 原样。
- 验收：普通管理员不能操作超级管理员或分配超出自身范围的角色；自定义业务角色按授权访问；停用、改密、账号 ID 错配、刷新重放和退出场景均有回归测试。

## 计划二：业务正确性与数据一致性

- 范围：编辑用户不改密码、字段清空、逻辑删除后的名称冲突、账号及菜单参数校验。
- 约定：已注销用户名、已删除角色编码及路由名称保留，不自动复用；重复创建返回明确业务错误。
- 数据更新：仅为确实可清空字段允许写入 NULL，不全局放开更新策略。
- 验收：空密码编辑可通过校验；短密码仍拒绝；公告撤回及个人资料清空生成正确更新 SQL；已删除名称冲突可识别。

## 计划三：文件存储与验证交付

- 范围：上传内容校验、文件事务补偿、日志脱敏与删除审计、关闭默认 SQL 标准输出、补充前后端测试。
- 文件策略：新文件在事务回滚时清理；旧文件在事务提交后删除；删除失败留下可检索日志并允许后续重试清理，不把物理删除纳入数据库回滚承诺。
- 验收：异常与回滚不删除旧头像；扩展名、MIME 和已支持格式内容校验一致；日志清空动作保留后续审计记录；测试、构建、lint 通过。
- 交付：更新需求、接口、数据库、部署、环境、测试报告及更新日志。真实 MySQL、浏览器与部署验证分别记录，不用单元测试代替上线验收。

## 执行与恢复

按计划一、二、三顺序实施，每阶段先修改代码并增加回归测试。发布前备份数据库和文件目录，在隔离测试库验证 V7 后再执行目标环境迁移。本轮不自动部署，不向既有业务库写入测试数据。

V7 生效后旧版 JWT 不再接受，用户需要重新登录。若回退应用，保留新增表列，不能删除 V7 历史或回改已执行迁移；安全缺陷版本不得作为常规恢复目标。
